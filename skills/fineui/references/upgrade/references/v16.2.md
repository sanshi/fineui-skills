# v16.2.0 升级检查

适用于目标版本为 v16.2.0 的 F.js、Pro、Core 三种模式和 Java 项目。先从依赖或资源确定源版本；跨过 v16.1.0、v16.1.1 时，还需检查 [v16.1 迁移](v16.1.md)。下面分开列出必须处理的兼容变化和可按需使用的新功能。

## 默认富文本编辑器

检索 `HtmlEditor`、`Editor`、`getEditorInstance`、`BasePath` 和 `Options`。省略 `Editor` 现在会使用 `Editor.Default`，客户端为 `editor: 'default'`。

- 采用新引擎时，核对保存过的 HTML。内置编辑器会规范化结构，并移除不支持的图片和表格。依赖这些内容、旧插件或第三方原生方法的页面应显式保留原编辑器。
- 原来的默认 UMEditor 页面可增加 `Editor="UMEditor"`；Java 为 `editor="UMEditor"`，F.js 为 `editor: 'umeditor'`。保留原 `BasePath`（F.js 为 `editorBasePath`）、选项和资源。
- 新引擎的纯 JS 页面，或关闭服务端 `IncludeEditorScripts` 的页面，须引入 `FineUI.HtmlEditor.css` 和 `FineUI.HtmlEditor.js`。
- 服务端取值使用 Pro/Core 的 `Text` 或 Java 的 `getText()`。`Value`、`EditorBasePath` 和 `HtmlEditorType` 不是 Pro/Core 的这组公开接口。
- `getEditorInstance()` 在内置模式返回 FineUI 适配器，不能继续调用 UMEditor、CKEditor 等引擎专用方法。旧引擎显式保留时仍返回对应原生实例。

[创建与工具栏配置](../../form/references/html-editor.md)

## jQuery UI 与指针事件

核心资源已移除 jQuery UI。检索业务代码的 `.draggable(`、`.resizable(`、`.sortable(`、`$.ui` 和直接操作 jQuery UI 数据的代码。页面需要这些插件时自行加载对应库；使用 FineUI 的公开窗体、布局和表格接口的代码按原配置运行。

FineUI 回调仍接收 `jQuery.Event`，底层 `originalEvent` 可能为 `PointerEvent`。自定义拖动完成回调应按公开参数处理，避免假定一定是 `MouseEvent`。使用 `FineUI_nojq.js` 时，宿主仍须先引入 jQuery。

核对窗体缩放、布局分隔条、分组表头调宽和列拖动。拖动中隐藏或删除控件会取消当前操作，不能依赖取消后继续收到完成事件。

## 表格列标识与 Java 列表绑定

仅 Core RazorForms/Java，回发中更改或清除已有列的 `ColumnID` 会报错。需要新业务列标识时创建新列并替换原列；原列 ID 和数据字段是不同概念，修改 `DataField` 时按实际数据重新绑定。

仅 Java，CheckBoxList 和 RadioButtonList 绑定 `null` 数据源后调用 `dataBind()` 会清空旧项目，与空集合一致。业务想保留旧项目时跳过本次绑定，不能再用 null 表示“本次保持原列表”。

Java 的 `Button.setClickCount/getClickCount` 已移除。需要累计业务点击次数时由应用保存，按页面和用户范围选择存储方式。

## 新功能接入时的限制

| 功能 | 升级后的选择 |
| --- | --- |
| 内置图表 | 新代码优先使用 `Chart`，按需加入 `FineUI.Chart.js/css`。显示选项创建时确定，后台通过数据绑定刷新。点击事件使用稳定业务键，不把数组下标当作记录标识。 |
| 文件拖放 | 创建时设置 `EnableDragDrop`。成功后再清空文件；失败保留选择供重试。核对普通提交与选定即上传两条流程。 |
| 企业版 Grid 行拖拽 | 创建时设置 `EnableRowMove`。核对当前页范围、排序/筛选/编辑等暂停条件。`rowmove` 只改变浏览器顺序，由业务决定何时保存。 |
| 页签标题排序与滚轮 | 滚轮浏览默认开启，可用创建开关 `EnableTabWheelScroll=false` 关闭。排序开启后，`ActiveTabIndex` 指新顺序，固定页面用对象或 ID 定位。 |
| 填写说明与下方错误 | 使用 `HelperText` 与 `MessageTarget.Under`。说明按纯文本处理，原输入及选择的文件应在更新说明后保留。 |
| Core MVC/RazorPages 复选列表 | AjaxHelper 新增 `Required(bool)`，可更新已有浏览器列表的必填规则。 |

## 跨过 v16.1.2 时一并核对

- 数字框及 `F/N/P` 格式按十进制四舍五入，中点远离零，例如 `-2.5 → -3`、`1.005 → 1.01`。依赖旧舍入结果的报表核对中点与负数。`F.formatNumber` 的第三参选项支持 `round: false` 向零截断和 `trimZero: true` 去尾零。
- Core RazorForms/Java 的生命周期与控件事件方法使用两个参数，分别为 `object/Object` 和对应 `EventArgs`。Java 的旧零参方法须迁移；异步方法返回合法的 `Future` 派生类型。
- Core RazorForms/Java 移除 `F.beforePostBack`。附带业务数据使用 `F.customEvent`；普通控件回发只发送其事件约定的 JSON 字段，无参事件省略参数，不能额外传 `{}`。
- 页面使用隐藏属性时，手工回发须携带当前 `__FHIDDEN`，不能误清空或漏传。业务高精度值按声明类型验证，Core 超出精度的 `decimal` 会被拒绝，Java 的 `BigDecimal` 读取代码须兼容科学计数法。
- 单/双触发框自动清除开启时，第一个触发按钮随文本显隐。需要手动控制它时先关闭自动清除，实际状态用 `isTriggerVisible(1)` 读取。
- Core/Pro 的旧 GIF 加载提示配置和大号/紧凑模式开关已废弃。新代码使用 `LoadingCSSNumber`、`DisplayMode`，客户端使用 `loadingCSS`。

## 验证与交付

按项目实际受影响功能验证正文编辑和保存、上传失败重试、图表点击权限、拖动取消、页签排序后的固定页定位，以及表单校验。Core 使用项目自身构建，涉及 Razor 视图时确认实际参与编译；Pro 用 Visual Studio MSBuild；Java 用项目 Maven/Gradle 构建。产品程序集、脚本、样式与插件资源保持同版，已打开页面刷新后再验证。
