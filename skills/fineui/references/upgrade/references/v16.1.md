# 从 v16.0.x 升级到 v16.1.0

按项目的实际版本和开发模式检查本页。FineUI.Java 首发为 v16.0，随后发布了 v16.0.1；本页包含这两个版本升级到 v16.1.0 时的 Java 服务端与客户端变化。使用候选包时先确认包含对应能力，后续版本另查实际发布历史。

## Core RazorForms：先调整页面入口

`Page_Init` 在首屏和每次控件回发都执行，且早于模板处理；`Page_Load` 在控件可用后执行。首次数据按用途放置：

| 数据或动作 | 放置位置 |
|---|---|
| 模板表达式、下拉数据源要读取的首次模型 | `Page_Init` 的 `!IsPostBack` 分支 |
| 页面配置、按当前网址校验记录和权限 | `Page_Init`，需要每轮校验时不加首次判断 |
| 首次给控件加载数据、设置默认值 | `Page_Load` 的 `!IsPostBack` 分支 |
| 保存、删除、用户点击后的动作 | 对应控件事件 |

每轮回发会再次处理实际 Razor 模板，取得控件声明与事件。模板中的 getter、`DataSource` 表达式仍可能执行，不能靠标签助手阻止查询；仅在 `OnGet` 创建的对象、已释放的一次性资源以及带副作用的表达式须调整。普通控件回发使用当前完整网址，保留查询参数。

动态事件应由当轮模板或服务器代码登记。条件、循环中的控件使用稳定、唯一的业务 ID；不要在脚本中依赖旧版自动生成的 `ct101` 等编号。会改变文字或参数的无名、重名表格命令，改用唯一 `CommandName` 或每轮在 `Page_Load` 重设。

参数错误或无权访问时可调用 `FineUI.Core.PageContext.AbortPage(message)`，然后立即 `return`。已有控件实例优先直接调用 `Grid1.AppendData(...)`、`Tree1.LoadData(...)`、`Window1.Show()` 等动作；整表绑定仍使用 `DataSource/DataBind()`。

## Core 模式、JSON 和脚本策略

删除页面内的 `PageManager.EnableRazorForms/EnableWebForms` 设置及其标签、流式写法，旧 setter 会报错。项目默认模式仍由全局配置决定；全局开启 Core RazorForms 时，需要原生 RazorPages 行为的页面在模型类或共同基类上添加可继承的 `[NoRazorForms]`。独立上传、下载、业务 JSON 接口无需为此添加标记。

Core 三种模式共用 JSON 首屏和 UI 响应。MVC/RazorPages 保留 Action/OnPost 与原生参数绑定，不执行 Core RazorForms 的模板重跑，也不上传该模式的控件状态。Core RazorForms 页面不能通过另一个 MVC/RazorPages UI 接口修改本页控件；独立业务 JSON 或文本接口使用原生 `fetch` 或 `jQuery.ajax`，不调用 `F.doPostBack`。

原来在 `AuthenticationTimeout` 等回调中搜索响应里的跳转 JS，现在应解析 JSON，检查 `commands` 中的 `page.redirect`。不要把 JSON 当脚本执行，也不要手工为 Core RazorForms 页面的普通按钮拼接 `handler`。

开启严格内容安全策略（Content Security Policy，CSP）后，使用控件动作、`ClientCommand` 和具名函数；MVC/RazorPages 的动态参数使用 `Parameter.FromFunction/FromEventArgument/FromData`。nonce 只授权可信脚本块，不放行 `eval/new Function`、内联事件或业务数据中的脚本。三种 Core 模式的 `CspScriptsAllowUnsafeEval` 未配置时均为 `false`，但类库本身不会自动开启 CSP；官方项目已显式开启。

Core RazorForms 的控件事件不再接受 `On...Parameter` 和 `Event.Parameters` 附加字段；额外浏览器数据用 `F.customEvent(name, payload)`，在 `Page_CustomEvent` 中读取。MVC/RazorPages 原生参数入口不受此项限制。

随官方项目分发的 `node tools/check-razorforms-upgrade.mjs .` 可只读扫描 Core RazorForms 的升级问题；它不自动修改代码，也不能代替实际浏览器检查。

## Java：生命周期与推荐方法

首次 `Page_Load` 改为完整 Thymeleaf 模板处理后执行。模板数据及页面配置移到 `Page_Init`；首次控件绑定仍放在 `Page_Load` 的 `!isPostBack()` 分支。旧 `Page_Get` 暂保留兼容，但仅在首屏调用，新代码使用 `Page_Init`。

| 旧入口 | 推荐入口 |
|---|---|
| Grid 的 `...RowId...`、Tree 的 `...NodeId.../...NodeIds` | `get/setSelectedRowID(Array)`、`get/setSelectedNodeID(Array)` |
| 列表的 `get/setSelectedValues`、DataList 的 `getSelectedItems` | `get/setSelectedValueArray`，多选使用 `String[]` |
| `getQueryParam/getQueryInt/getQueryLong` | `getQueryValue/getQueryIntValue/getQueryLongValue`，另有 `getQueryBoolValue` |
| 页面基类的 `addCss/redirect/invokeFunction/invokeParentFunction` | `PageContext` 同名方法 |
| `invokeClientFunction` | `PageContext.invokeFunction` |
| `getCspScriptsNonceValue()` | 普通模板内联脚本无需手工取值；确需取值时用 `PageManager.current().cspScriptsNonceValue()` |
| `AbortPageException` | `PageContext.abortPage(...); return;` |
| `ActiveWindow.hide*Reference` 等延后动作 | 对应 `ActiveWindow.*Command` |
| 已移除的 `hideComponent(id)` | 取得控件实例并调用 `hide()` |
| 消息类已移除的 `getShowReference/getShowInTopReference/getShowInParentReference` | `show(...)`、实例 `show()`，回调使用具名函数或 `setOkCommand(...)` |

`DataList.getSelectedValueArray()` 的返回值从 `List<String>` 改为 `String[]`，把 `isEmpty()/get(i)` 改为 `length/[i]`。清空时用 `new String[0]`，避免 `null` 在保留的新旧重载间无法确定。

Java 可继承的尺寸、间距、步长、标签及列锁定配置使用可空包装类型；未设置的宽高、坐标、图片尺寸、按钮 TabIndex 返回 `null`。读取后先判空，不把 `null` 和明确的 `0` 混为一谈。图标地址 getter 返回原始地址，需要解析应用路径时调用 `IconHelper.resolveUrl(...)`。

`TextMode`、`InputType` 分别保留原值，非空 `InputType` 决定浏览器输入类型。`TriggerBox.trigger-icon` 只接受六种内置图标名，自定义类名用 `trigger-cls`。手写正则默认忽略大小写，需要区分时明确设置 `regex-ignore-case="false"`。

## 表格、事件和布局

内置控件事件使用具名 JSON 参数；框架自动生成的事件无需修改，手工拼接 `paging$...`、`rowcommand$...` 的代码改用公开控件事件或 `F.customEvent`。Java 普通事件使用 `getArgument("字段名")` 或专用 EventArgs，不再按位置拆分参数；页面级 CustomEventArgs 的原有分段读取不变。

Core RazorForms 和 Java 的 `ColumnIndex/getColumnIndex()` 是点击时当前可见叶子列的位置，拖动或隐藏后会变化；操作分支使用 `CommandName`。需要按列名定位无字段或重复字段的列时，显式设置 `ColumnID/column-id`。Core 显式列名须在整个列树唯一，点号转下划线后也不能冲突。

Core 的 `PageSizeOptions` 从 `string[]` 改为 `int[]`：

```csharp
Grid1.PageSizeOptions = new[] { 5, 10, 20 };
```

标签可写 `_PageSizeOptions="5,10,20"`，MVC 流式用 `.PageSizeOptions(5, 10, 20)`。Core/Java 均只接受正整数，`null`、空数组使用默认选项；它只在创建分页栏时生效，不能动态更新现有分页栏。Pro 的类型不变。

Core/Pro 的 `TabIndex` 改为 `int?`，`TimePicker.Increment` 改为 `int`，相应变量和旧程序集引用须调整并重新编译。四端默认每页 20 行、双击编辑、时间间隔 15 分钟、主题 `pure_black`；F.js/Java 的 HtmlEditor 默认工具栏为 `Basic`，需要完整工具栏时显式设置 `Full`。

Pro/Core 的 FormRow 不再为按钮自动包装 Panel。未指定 `ColumnWidths` 或设置 `50% 50%` 时，两个控件仍均分，但按钮也会占半行。需要字段占剩余宽度、按钮保持内容宽度时：

```cshtml
<f:FormRow ColumnWidths="100% auto">
    <Items>
        <f:TextBox ID="SearchText" Label="关键词"></f:TextBox>
        <f:Button ID="SearchButton" Text="查询"></f:Button>
    </Items>
</f:FormRow>
```

MVC 使用 `.ColumnWidths("100% auto")`；Pro 保留 `runat="server"`。Java 原本直接布局，只增加相同的 auto 列宽能力；`50% auto` 不是保持窄按钮效果的通用替代。

表格重绑及带数据源换列遵守 `ClearSelectionBeforeBinding`，默认清除全部旧行和单元格选择；需要跨页保留时明确设为 `false`。明确清空数据用 `ClearData/clearData`，清除全部选择用 `ClearSelections/clearSelections`，不要用仅清当前页的 `DeselectAllRows/deselectAllRows` 代替。Core RazorForms 页面需要合计值时，应重新计算并设置 `SummaryDataArray`。

## 空值、日期与 HTML 显示

- 单选列表未选择是 `null`，选中真实空值项是 `""`；判断未选择使用 `value == null`。DropDownBox 的 `setText` 用自由文字替换旧选择，需要保留值和逐项文字时使用 `SetSelection/setSelection` 或客户端 `setValue(value, text)`。
- Core/Java 的 Calendar、DatePicker 按当前格式保存日期及上下限。先设置格式，再赋日期；格式舍弃的时分秒不会在扩展格式时恢复。范围任一端为 `null` 清空整个范围，单改一端保留当前另一端。
- Core/Java 的 `XxxRawHtml=null` 同时清空文字与关闭 Raw 标记；只想关闭 HTML 显示而保留文字时设置 `XxxRaw=false`。仅修改文字不会关闭原标记，回传标记不能证明内容可信，仍需验证来源及编码或清洗。
- Core 的 `RegexPattern` 使用固定内置规则，大小写开关只影响手写 Regex；不能用 `RegexIgnoreCase` 改变 `ALPHA_LOWER_CASE` 等内置规则。
- Tab、AccordionPane 内容区固定无圆角；Core/Java 的 Accordion、Form、SimpleForm、Grid、RegionPanel、TabStrip、Tree 不直接承载 iframe。需要 iframe 时使用内部 Panel 或支持的 Window、Tab、AccordionPane、GroupPanel、Region。
- Core 的 `ActiveTab/ActivePane` 不再接受 `null` 或外部对象；先加入当前容器集合，再设置激活对象。菜单默认隐藏，由所属按钮或右键动作打开。

Core MVC/RazorPages 的 UIHelper Raw 相关文字方法改为可选 `bool?` 参数：省略或 null 保留原 Raw，false/true 才同时修改；可用 `XxxRaw(bool)` 单改标记，`XxxRawHtml(null)` 清空并撤销标记。Label、HyperLink、LinkButton 移除旧服务器编码参数；旧 `Text(html, true)` 仍可能编译成功，含义却变成 Raw=true，须逐处检查并按需要显式调用编码函数。此项只涉及 UIHelper，不改变 Core RazorForms 控件属性、标签或流式创建接口。

## 升级后的验证

重新编译项目，并在实际页面检查首次加载、连续回发、清空和重置、表格选择与换列、弹窗回调、上传下载，以及桌面和窄窗口下的按钮布局。启用 CSP 时同时检查响应头、模板脚本执行和浏览器控制台；HTTP 200 不等于脚本已正确运行。

服务器 DLL/JAR 和客户端资源须一起更新或回滚，升级后刷新旧页签。保存请求失败且结果不明确时，先核对业务结果，不自动重新提交。
